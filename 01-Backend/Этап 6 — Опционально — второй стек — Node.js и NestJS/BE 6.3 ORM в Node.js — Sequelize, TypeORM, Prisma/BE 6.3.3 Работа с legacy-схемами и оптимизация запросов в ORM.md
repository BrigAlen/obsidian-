## Объяснение

### Legacy-схема

- Интроспекция: `prisma db pull`, `typeorm-model-generator`, `sequelize-auto` создают модели по существующей БД.
- Несоответствие имён: `@map`, `field`, `underscored` для snake_case и нестандартных ключей.
- Составные ключи, отсутствие внешних ключей, нетипичные типы (`char(1)` как boolean) — описывайте явно и оборачивайте в доменные типы.
- Не запускайте авто-миграции на чужой схеме; изменения — вручную и согласованно.
- Представления (views) и хранимые процедуры подключайте как read-only модели/raw-вызовы.

### Оптимизация запросов

| Проблема | Решение |
|---|---|
| N+1 | жадная загрузка, `select`/проекции, DataLoader |
| Лишние колонки | `select`/`attributes` |
| Отсутствие индекса | `EXPLAIN ANALYZE`, индекс по фильтру и сортировке |
| Большие `IN`/offset | keyset-пагинация, временные таблицы |
| Много мелких запросов | батчинг, `createMany`, `bulkCreate` |
| Медленный запрос в ORM | raw SQL с параметрами |
| Долгие транзакции | короткие, без внешних вызовов |
| Пул соединений | размер по числу реплик и лимиту БД, PgBouncer |

```ts
// логирование SQL и подсчёт запросов
const prisma = new PrismaClient({ log: [{ emit: "event", level: "query" }] });
prisma.$on("query", (e) => logger.debug(`${e.duration} ms: ${e.query}`));
```

Метод: включить лог SQL → найти повторяющиеся и медленные запросы → `EXPLAIN` → исправить запрос/индекс → повторить замер.

## Нюансы и подводные камни

- ORM скрывает SQL, но не отменяет необходимости понимать индексы и планы.
- Изменение схемы «вручную» в БД и в ORM должно идти вместе.
- Кэширование результата ORM в памяти приложения ведёт к устаревшим данным.
- Массовые изменения — через SQL/bulk, а не циклом `save()`.

## Практика

1. Подключите Prisma к существующей БД через `db pull`.
2. Найдите N+1 и медленные запросы по логам.
3. Перепишите цикл `save` на пакетную операцию.

## Вопросы с ответами

> [!question]- Как подключить ORM к legacy-БД?
> Интроспекция схемы, явный маппинг имён и типов, отсутствие авто-миграций, при необходимости raw SQL.

> [!question]- Как найти проблемные запросы?
> Логировать SQL, считать запросы на операцию, смотреть `EXPLAIN ANALYZE`.
