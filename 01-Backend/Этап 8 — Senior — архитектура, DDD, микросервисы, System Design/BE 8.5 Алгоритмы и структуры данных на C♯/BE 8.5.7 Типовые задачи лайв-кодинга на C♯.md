## Объяснение

**Как вести себя на live coding**:

1. Переформулируйте условие и уточните ограничения (размер входа, пустые данные, дубликаты, отрицательные числа).
2. Разберите пример вручную.
3. Предложите простое решение и его сложность, затем оптимизацию.
4. Пишите чистый код с осмысленными именами; проговаривайте ход.
5. Проверьте на примере и крайних случаях; назовите сложность по времени и памяти.

**Набор типовых задач и приёмов**:

| Задача | Приём |
|---|---|
| Two Sum, дубликаты, анаграммы | хэш-таблица |
| Валидные скобки | стек |
| Обратить связный список, найти цикл | указатели, fast/slow |
| Слияние интервалов | сортировка по началу + проход |
| Максимальный подмассив (Kadane) | ДП/жадность за O(n) |
| Поиск в повёрнутом массиве | бинарный поиск |
| Top-K, медиана потока | куча |
| LRU-кэш | `Dictionary` + `LinkedList` |
| Сериализация/десериализация дерева | BFS/DFS |
| FizzBuzz, разворот строки | базовые циклы и `StringBuilder` |
| Потокобезопасный счётчик/кэш/producer-consumer | `lock`, `Interlocked`, `Channel` |
| Ограничитель параллелизма | `SemaphoreSlim` |

```csharp
// Валидные скобки
static bool Valid(string s)
{
    var st = new Stack<char>();
    var pair = new Dictionary<char, char> { [')'] = '(', [']'] = '[', ['}'] = '{' };
    foreach (var c in s)
    {
        if (pair.TryGetValue(c, out var open)) { if (st.Count == 0 || st.Pop() != open) return false; }
        else st.Push(c);
    }
    return st.Count == 0;
}

// Слияние интервалов
static int[][] Merge(int[][] iv)
{
    var res = new List<int[]>();
    foreach (var x in iv.OrderBy(i => i[0]))
        if (res.Count > 0 && x[0] <= res[^1][1]) res[^1][1] = Math.Max(res[^1][1], x[1]);
        else res.Add([x[0], x[1]]);
    return res.ToArray();
}

// Kadane
static int MaxSubArray(int[] a) { int cur = a[0], best = a[0]; for (int i = 1; i < a.Length; i++) { cur = Math.Max(a[i], cur + a[i]); best = Math.Max(best, cur); } return best; }
```

Подготовка: 60–80 задач по темам (массивы/хэш/указатели/стеки/деревья/графы/куча/ДП), таймер 30 минут, разбор решений вслух.

## Нюансы и подводные камни

- Молчаливое решение: интервьюер не видит ход мысли.
- Оптимизация раньше корректности.
- Пропуск граничных случаев: пустой ввод, один элемент, переполнение.
- Игнорирование сложности и памяти.
- Использование LINQ там, где важна производительность или понятен цикл.

## Практика

1. Решите 10 задач из таблицы за две недели, записав сложность каждой.
2. Проведите пробное live coding с коллегой или голосовой записью.
3. Реализуйте LRU-кэш и thread-safe вариант.

## Вопросы с ответами

> [!question]- Что делать, если не знаешь решение?
> Начать с полного перебора, проговорить идею, затем искать оптимизацию; показывать ход мысли и уточнять условия.

> [!question]- Что оценивают на live coding?
> Понимание задачи, чистоту кода, сложность, работу с крайними случаями и общение.
