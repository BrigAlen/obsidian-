## Объяснение

| Инструмент | Особенности |
|---|---|
| Flyway (Java, CLI, контейнер) | SQL-файлы `V1__init.sql`, версионирование, чексуммы |
| goose (Go) | SQL/Go-миграции, `up`/`down` |
| EF Core Migrations | C#-миграции, idempotent-скрипты, bundle (см. [[N:3ea33104867981e88c8ffcdc0440cf35]]) |
| Liquibase, DbUp, Atlas | альтернативы |

Правила выкладки:

- Миграции **отдельным шагом** до запуска новой версии (init-контейнер/job), а не из каждого экземпляра приложения.
- Миграции **идемпотентны и версионированы**, применённые файлы не редактируются.
- Хранятся в репозитории рядом с кодом.

### Обратная совместимость (expand → migrate → contract)

1. **Expand**: добавить новое (колонка nullable, новая таблица) — старый код работает.
2. Выкатить код, пишущий в старое и новое (или читающий новое).
3. **Migrate**: перенести данные пакетами.
4. **Contract**: после полного перехода удалить старое отдельной миграцией.

| Операция | Безопасно? |
|---|---|
| ADD COLUMN NULL | да |
| ADD COLUMN NOT NULL без default | нет (блокирует, ломает старый код) |
| RENAME/DROP COLUMN | нет: через expand/contract |
| CREATE INDEX | в PostgreSQL — `CONCURRENTLY` |
| Изменение типа | пересоздание колонки поэтапно |

## Нюансы и подводные камни

- Долгие блокировки (`ALTER TABLE` на больших таблицах) останавливают прод.
- Откат «вниз» миграции данных часто невозможен: планируйте прямые исправления.
- Одновременная работа двух версий приложения при rolling-обновлении требует совместимости.
- Тестируйте миграции на копии реальных объёмов данных.
- Блокировка на уровне миграций (advisory lock) предотвращает параллельный запуск.

## Практика

1. Переименуйте колонку через expand/contract на тестовой БД.
2. Настройте job миграций в CI/CD перед деплоем.
3. Создайте индекс на большой таблице без блокировки.

## Вопросы с ответами

> [!question]- Как менять схему без простоя?
> Обратно совместимыми шагами (expand/contract) и короткими неблокирующими операциями.

> [!question]- Почему не применять миграции из приложения при старте?
> Гонки между репликами, долгие DDL при старте и сложный откат; лучше отдельный контролируемый шаг.
