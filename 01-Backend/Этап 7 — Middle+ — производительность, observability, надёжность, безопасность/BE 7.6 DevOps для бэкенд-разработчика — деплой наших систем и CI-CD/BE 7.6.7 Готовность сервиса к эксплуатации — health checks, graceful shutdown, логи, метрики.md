> [!info] Зачем это на собесе
> Чек-лист «production readiness»: что должен уметь сервис, чтобы его можно было безопасно эксплуатировать.

## Объяснение

| Область | Требование |
|---|---|
| Здоровье | `/health/live` и `/health/ready` (см. [[N:3ea33104867981e0adc9fe8799f5ec40]]) |
| Остановка | graceful shutdown: завершение запросов и консьюмеров по SIGTERM (см. [[N:3ea331048679819b82adf7f42ef440d8]]) |
| Логи | структурные JSON в stdout, `trace_id`, без секретов |
| Метрики | RED-метрики, runtime, бизнес-метрики, экспорт (Prometheus/OTLP) |
| Трейсы | OpenTelemetry, проброс контекста |
| Конфигурация | через окружение, валидация при старте |
| Ресурсы | requests/limits, лимиты пула и потоков |
| Отказоустойчивость | таймауты, ретраи, circuit breaker, идемпотентность |
| Безопасность | не root, секреты вне образа, минимальные права, актуальные зависимости |
| Данные | миграции совместимы, бэкапы проверены |
| Документация | README, runbook, алерты со ссылками |
| Версия | в `/health`, метриках и логах |
| Масштабирование | stateless, состояние вне процесса |

Runbook: что делать при типовых инцидентах (рост ошибок, задержки, переполнение очереди, недоступность БД) — шаги диагностики и восстановления.

## Нюансы и подводные камни

- Readiness, зависящий от неважной зависимости, выводит сервис из балансировки без причины.
- Отсутствие лимитов ресурсов: один сервис «съедает» узел.
- Логи только в файлы внутри контейнера теряются при перезапуске.
- Нет алертов на симптомы — узнаёте об инциденте от пользователей.

## Практика

1. Пройдите чек-лист по своему сервису и заведите задачи на пробелы.
2. Напишите runbook для двух самых вероятных инцидентов.
3. Проведите тест перезапуска зависимостей (chaos-lite).

## Вопросы с ответами

> [!question]- Что значит «готов к эксплуатации»?
> Сервис наблюдаем, корректно стартует и останавливается, устойчив к сбоям зависимостей, безопасен и имеет документированный процесс реагирования.

> [!question]- Что такое runbook?
> Пошаговая инструкция диагностики и восстановления для типовых инцидентов.
