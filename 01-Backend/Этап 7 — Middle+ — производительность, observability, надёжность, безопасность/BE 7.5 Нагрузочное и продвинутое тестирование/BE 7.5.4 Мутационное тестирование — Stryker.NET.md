## Объяснение

Мутационное тестирование вносит небольшие изменения (мутации) в код и запускает тесты. Если тесты падают — мутант «убит»; если проходят — «выжил», значит тесты этого изменения не замечают.

| Мутация | Пример |
|---|---|
| Арифметика | `a + b` → `a - b` |
| Сравнение | `>` → `>=` |
| Логика | `&&` → `||` |
| Возврат | `return x` → `return default` |
| Удаление оператора | вызов метода удаляется |

**Mutation score** = убитые / (убитые + выжившие) × 100%.

```bash
dotnet tool install -g dotnet-stryker
cd tests/Orders.Tests && dotnet stryker --break-at 60      # падает, если score < 60%
```

Результат — HTML-отчёт: какие мутанты выжили и в какой строке.

```csharp
public decimal Discount(decimal total) => total >= 1000 ? total * 0.1m : 0;   // выживший мутант: >= → > , если нет теста на 1000
```

Улучшайте тесты, добавляя граничные случаи и проверки результата.

## Нюансы и подводные камни

- Запуск долгий: применяйте на изменённом коде (`--since`), в ночных сборках, для критичных модулей.
- Эквивалентные мутанты (не меняют поведение) дают ложные «выжившие».
- 100% score не цель; смотрите на выжившие в важной логике.
- Медленные и нестабильные тесты замедляют всё.
- Дополняет, а не заменяет покрытие кода.

## Практика

1. Запустите Stryker на модуле расчётов и разберите выживших.
2. Допишите тесты на граничные значения и убейте мутантов.
3. Настройте порог в ночном CI.

## Вопросы с ответами

> [!question]- Что такое выживший мутант?
> Изменение кода, которое не привело к падению тестов, что показывает пробел в проверках.

> [!question]- Чем mutation score лучше coverage?
> Coverage показывает выполнение кода, mutation score — способность тестов обнаружить ошибки.
